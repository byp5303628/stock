# 03. 财报指标存储

## 1. 背景与目标

### 1.1 业务背景

在建设完整的股票分析体系过程中，财报数据是基本面分析的核心输入。当前系统已有日 K 线数据（前复权/后复权）和交易策略回测能力，但缺乏对上市公司财务报表数据的结构化存储和管理能力。

现金流量表、资产负债表、利润表这三张核心财务报表的指标数据，目前没有统一的存储模型。分析场景（如策略回测中的基本面过滤、指标计算）无法直接获取和使用财报数据。

### 1.2 业务目标

建设财报指标数据的结构化存储能力，满足以下目标：

- 对三张核心财务报表（现金流量表、资产负债表、利润表）的指标进行格式化存储
- 基于元数据系统（feature-03）定义财报数据模型，支持模型持续扩展
- 确保每条数据仅存储一次季度财报，避免重复存储
- 确定数据获取来源，支撑后续分析场景的数据消费

## 2. 需求范围

### 2.1 In Scope

- 现金流量表、资产负债表、利润表三张报表的数据模型定义（使用元数据系统）
- 财报数据模型的持久化存储
- 数据去重：同一只股票同一季度财报仅存储一次
- 数据获取来源的调研与确定

### 2.2 Out of Scope

- 财报数据的可视化展示页面（前端报表页面）
- 财报指标的分析计算（如财务比率计算）
- 财报数据的自动更新与定时同步
- 历史财报数据的批量补录与迁移
- 除三大报表外的其他财务数据（如附注、审计意见等）

## 3. 业务规则

### 3.1 数据覆盖范围

- 如果一份数据属于现金流量表、资产负债表、利润表中的一项，则该数据应被纳入本系统的存储范围
- 如果一份数据不属于上述三张报表，则该数据不属于本系统的存储范围（属于 Out of Scope）

### 3.2 数据模型（元数据）

- 如果需要在系统中存储某张报表的指标，则通过元数据系统（见 feature-03：建设标准的元数据系统）创建对应的元数据模型，定义字段名称、类型、业务含义
- 如果未来需要新增报表类型或指标字段，则通过扩展元数据模型实现，无需修改存储层代码

### 3.3 数据存储

- 如果某只股票在某个自然季度发布了财报，则该条财报数据应以「股票代码 + 财报所属季度」为唯一标识，仅存储一条记录
- 如果重复提交同一只股票同一季度的财报数据，则系统应去重（后提交的覆盖前一次或忽略，视具体策略而定）

### 3.4 数据获取

- 如果确定使用公开数据源获取财报数据，则数据源应稳定可靠且允许非商业使用
- 如果数据源接口返回的数据结构与本系统模型不一致，则需要做字段映射和格式转换

## 4. 验收条件

### 4.1 数据模型定义

- Given 元数据系统中已创建「现金流量表」模型，When 查看该模型的定义，Then 应包含该报表所有核心指标的字段名、类型和业务含义
- Given 元数据系统中已创建「资产负债表」模型，When 查看该模型的定义，Then 应包含该报表所有核心指标的字段名、类型和业务含义
- Given 元数据系统中已创建「利润表」模型，When 查看该模型的定义，Then 应包含该报表所有核心指标的字段名、类型和业务含义

### 4.2 数据存储

- Given 通过数据获取接口提交一只股票某一季度的财报数据，When 提交成功，Then 该数据被持久化存储并可查询
- Given 已存在一只股票某一季度的财报数据，When 再次提交同一季度同一股票的相同数据，Then 系统不产生重复记录（去重生效）

### 4.3 模型扩展

- Given 元数据系统中已存在三张报表的模型，When 需要新增一个报表指标字段，Then 通过元数据系统新增字段即可，存储层无需变更

## 5. 非功能性要求

| 要求类别 | 指标 | 目标值 |
|----------|------|--------|
| 数据准确性 | 季度财报数据与数据源保持一致 | 100%（无数据丢失或错位） |
| 数据一致性 | 股票代码 + 季度的唯一约束 | 无重复记录 |
| 可扩展性 | 新增报表类型或字段 | 无需修改代码，仅通过元数据配置完成 |
